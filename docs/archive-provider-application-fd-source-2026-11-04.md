# Archive-mirror application-owned credential FD adapter — source handoff

2026-11-04 · [archive-mirror #2](https://github.com/zog144/archive-mirror/issues/2) · [host-install PR #23](https://github.com/zog144/host-install/pull/23) · [root-control PR #31](https://github.com/zog144/root-control/pull/31)

**DISABLED SOURCE CANDIDATE; no real credential transfer or protected native installation.** The archive consumer/purpose is `archive-mirror` / `archive-mirror-upstream-fetch`, never `certify-manage` or `issuer-cloudflare-dns01`. The existing in-memory `provider_credentials.install_verified` remains a separately reviewed legacy source interface and is **not called** by the new FD adapter.

## Application-owned steps and trust boundary

`src/zog/archive_mirror/provider_credential_fd.py` exposes `receive_and_install_once` (one-shot, no listen/bind), `install_verified_fd` (application-owned private FD installation), and private bounded metadata/FD checks. Both entrypoints fail closed by default with `enabled=False`; selecting `enabled=True` in a synthetic test **does not** authenticate root-control's authority or install a native service.

A future protected root receiver must independently pin exact Host, HostIdentity, installation, STATE, registry, archive role/collection, current canonical signed authorization and revocation, original sender process identity, and one irreversible request/delivery/**installing** fence BEFORE ever sending a credential FD. That trusted native owner also owns the authentication/provenance of an immutable source policy and current approval. The adapter intentionally cannot discover or replace those pins itself.

A socket caller must present an `AF_UNIX SOCK_SEQPACKET` connection with kernel `SO_PEERCRED` matching an authorized root UID/GID, exactly **one** SCM_RIGHTS FD, a canonical bounded metadata frame with no secret/secret-format fields, an exact archive-only scope and canonical request/delivery metadata, and a matching claimed durable pre-install fence. All unexpected FDs are closed on denial. A received descriptor must be anonymous (`st_nlink=0`, memfd pathname) with all four `F_SEAL_*` protections and an exact bounded size; named, unsealed and oversized file descriptors are rejected. Its contents are read with `pread` **inside the archive application process**, hashed and streamed into the archive application's private 0600 file under its normal 0700 directory and per-scope lock. The in-memory secret is never passed in Python authorization/delivery JSON or returned in an acknowledgement.

The application's existing `_active_role`, scope, predecessor rotation, revocation tombstone, private inode, fsync and atomic publication checks remain in force. An already pending installation, completed delivery replay or an ambiguous outcome cannot be reinstalled with a second FD. Bad hash/short FD after pending record is deliberately **fail closed**; recovery requires independent installed-byte observation and the original root owner's decision, not retransmission.

Successful local installation returns only `status=installed-receipt-pending`, scope/delivery/revision and `native_acknowledged=false`. This is *not* a signed native installation receipt or byte witness. The actual attested application-origin response required by host-install PR #23 and root-control PR #31 still needs separately protected application process identity, signed acknowledgement sequence/nonces, durable native byte witness, validated original root sender, boot/InvocationID fencing and authenticated installed source. Revocation uses the existing application-owned `apply_signed_revocation` with independently pinned authority key and durable common deny BEFORE app revocation; no secret FD is transferred for revocation. Role removal never deletes the archive objects, catalogue or pins.

## Source evidence and native holds

CI exercises the actual private archive store under a **non-root** account on Python 3.12 and 3.13. Synthetic sealed memfd tests cover installation, secret-free receipts, no repeated delivery, wrong purpose/scope/UID, unsealed descriptors, installed revocation and a separate process. The separate-process positive test hands an inherited test FD to another nonroot child; the negative kernel-peer test proves an unprivileged process cannot claim root `SO_PEERCRED`. Neither proves successful root-to-nonroot SCM_RIGHTS delivery or installs a dedicated application unit. An independent signed native installed-byte acknowledgement remains absent.

**NO-GO**: no protected application UID/GID selected, real root receiver/peer, authenticated physical STATE, service/socket installation, signer identity, actual provider token, network transport or native application receipt. The adapter remains disabled outside isolated source tests; [archive-mirror issue #2](https://github.com/zog144/archive-mirror/issues/2) stays open.
